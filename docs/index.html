Who says yes to a term deposit?

Can a bank's records rank clients before it phones them, and does that ranking still work a year later?

ES 335 project by Bhukya Bhavyasree · Bank Marketing data, UCI Machine Learning Repository

Short answer. Yes, but only a little. On the most recent fifth of the file, a logistic regression reaches ROC-AUC and PR-AUC . A one-line rule, “call the people who said yes last time”, scores and , and the PR-AUC gap between the two is inside bootstrap noise. Gradient boosting, the more complex model, scores lower than both on PR-AUC ().

Why it is hard. The share of clients who subscribed climbed from in the training period to in the test period, while interest rates fell to levels the models never saw. Scrambling the rows into a random split hides all of this and reports an AUC of about .

Question

Using only what a Portuguese retail bank knows about a client before it dials, and the economic conditions that day, can we rank clients by how likely they are to subscribe to a term deposit, and does a ranking learned on earlier campaigns still work on later ones?

Phone calls cost agent time, and most clients say no. A useful ranking lets the bank spend a fixed number of calls where they pay off most. A useful answer to this project is not “the model is accurate” but “the model beats a trivial baseline on a later period, by this much, with this uncertainty, and fails in these places”.

One row
One client in one marketing campaign, described by their last contact: who they are, how they were reached, their history with the bank, and the outcome.
Target
y: did the client subscribe to a term deposit (yes or no)?
Prediction time
Just before a call is placed.
Known at that time
Age, job, marital status, education, credit and loan flags, contact channel, calendar month and weekday, history from earlier campaigns, and public economic indicators (employment variation, consumer price and confidence indices, 3-month Euribor, employment level).
Not known
duration (how long the call lasted) exists only after the call. campaign counts the contacts made to this client including the last one, so for a row it is only final once the client's contacts have ended. Neither is used by the main models. The data section shows why, and the results section measures what using them would have done.
Limits of the claim
This describes association in one bank's 2008–2010 campaigns. It does not say why a client subscribes, and it says nothing about clients the bank never called.

Data

Source and access. The Bank Marketing dataset in the UCI Machine Learning Repository (Moro, Rita and Cortez, 2014), file bank-additional-full.csv. It records phone campaigns run by a Portuguese retail bank between May 2008 and November 2010. It is free to download without an account under a CC BY 4.0 licence, contains no names or contact details, and a copy is included in this repository with attribution.

Quality checks

What the training block shows

The next chart uses the training block only (the first 60% of rows, May–November 2008), so that no exploration is done on rows reserved for validation or testing. It is descriptive. A group with a higher rate is not one that is caused to subscribe more. Contact channel, for example, changes over time along with everything else.

Two variables I leave out, and why

duration is the strongest single column: on its own it separates subscribers from non-subscribers with ROC-AUC in the training block. That is the warning sign. A call lasts long because the client is interested, so a model using it answers “who talked longest?”, which the bank only learns after dialling. The dataset's own documentation says it should be dropped for realistic prediction.

campaign includes the final contact, so a client who subscribes early has a low count and one who never does keeps accumulating calls. In the training block it carries almost no signal anyway (ROC-AUC when inverted), so leaving it out costs little.

The economy columns move together

The five economic indicators are strongly correlated (training block). That is harmless for tree models but makes a linear model's individual coefficients unstable, which is one reason I treat them as a bundle (included or excluded together) rather than picking them one by one.

Preprocessing

  • “unknown” stays a category. There are no empty cells, so there is nothing to impute. Replacing “unknown” with the most common value would invent data and erase a pattern that may carry information.
  • pdays becomes two columns. The value 999 means “never contacted”, so treating it as a number would say these clients were last contacted 999 days ago. I use a never-contacted flag and a days-since column that is 0 for those clients.
  • Categories are one-hot encoded (ten categorical columns). Levels are learned from the fitting rows. A level seen only later, such as September, which first appears in the test block, becomes all zeros rather than an error.
  • Numeric columns are standardised using the fitting rows' mean and spread. This matters for the penalised logistic regression. It is harmless for trees.
  • Excluded: duration, campaign and the derived year (see Data). Nothing else is dropped.
How leakage is prevented

Every learned step (scaler, category levels, model weights) lives inside one scikit-learn Pipeline that is fitted on the rows of the fitting block only. The validation block is used to choose settings. The test block is scored once, at the end, by models refitted on train plus validation. The category-rate chart above uses the training block only.

pre = ColumnTransformer([
    ("num", StandardScaler(), numeric_cols),
    ("cat", OneHotEncoder(handle_unknown="ignore", sparse_output=False), categorical_cols),
])
model = Pipeline([("pre", pre), ("clf", LogisticRegression(C=C))])
model.fit(df.iloc[fit_rows], y.iloc[fit_rows])      # scaler and categories learned here only
scores = model.predict_proba(df.iloc[eval_rows])[:, 1]

Statistical reasoning. The only inferential statistic in this project is the bootstrap, used on the test block to put intervals on the metrics and on differences between methods (see Evaluation). I use no significance tests on the descriptive charts, because they would answer a question I am not asking.

Baseline and methods

Four things are compared. The first two are baselines a model has to beat before its complexity is justified.

MethodCore ideaAssumptions and why it fits
No-skill baselineGive every client the same score.Ranking quality is then pure chance: ROC-AUC 0.5, and PR-AUC equal to the share who subscribe. This is the floor for the imbalanced-data metrics.
Previous-success ruleScore 1 if the previous campaign ended in success, else 0.A bank manager would try this first. It assumes past behaviour repeats and ignores everything else. If a model cannot beat it, the extra machinery adds nothing.
Logistic regressionFit weights that minimise log-loss plus an L2 penalty; smaller C shrinks harder.Assumes the log-odds of subscribing are a sum of effects of the features. Few parameters, stable when the data shifts, and each weight can be read. A natural first real model for 25,000 rows of tabular data.
Gradient-boosted treesAdd many small trees, each fitted to the errors of the ones before.Learns interactions and non-linear effects without being told. It assumes the training rows resemble the rows it will be used on. A tree cannot extrapolate: a value outside the training range is treated like the nearest edge.

What I tuned, and how

Settings are chosen on the validation block by PR-AUC. Logistic regression tries six values of C. Gradient boosting tries 24 combinations of learning rate, tree size, L2 penalty and number of trees. Each is tried with and without the five economy indicators, because I could not tell in advance whether they help or merely stand in for the date. The figure shows all 60 configurations.

Validation chose the version without the economy indicators for both models. Logistic regression is the stronger of the two on validation, so it is the primary model. I did not try neural networks or larger ensembles: with about 25,000 training rows, a handful of weak signals and a strong shift in the data, more flexibility is a liability, not an advantage.

Evaluation

Design. The deployment situation is “learn from past campaigns, call clients in future ones”, so the split follows time: the first 60% of rows to train, the next 20% to choose settings, the last 20% as a test I look at once. Split points are row and row .

What I did not change

I looked at the share of subscribers in each block before fitting any model, and that is how I found how large the drift is. I kept the planned 60/20/20 split anyway. Moving the cut points to make the test block look more like the training block would mean choosing the evaluation after seeing the answer. Instead, the random split and the rolling cut-offs further down are reported as extra views, clearly labelled.

Procedure

  1. Fit each candidate on the training block, score the validation block, pick the best settings by PR-AUC.
  2. Refit the chosen settings on training plus validation. The most recent rows matter most when conditions drift.
  3. Score the test block once and report. Nothing in step 3 feeds back into steps 1–2.

Metrics, and why these

  • PR-AUC (average precision) rewards putting subscribers at the top of the list, and suits a rare positive class. It is read against the no-skill line, which equals the share of subscribers. Here that is on the test block, so the same PR-AUC means different things in different periods.
  • ROC-AUC is the chance that a random subscriber is ranked above a random non-subscriber. It does not depend on how common subscribers are, so it is the fairer number when that share moves.
  • Reach and precision at a call budget: if the bank can only call the top 20%, how many of the calls succeed, and how many of all subscribers are reached? This is the operational question.
  • Brier score and calibration check whether the scores can be read as probabilities. They cannot here (see Results).
  • Not used: accuracy. Always answering “no” is accurate on the test block and on the training block. The number mostly measures how rare subscribers happen to be.

Uncertainty

Intervals come from bootstrap resamples of the test rows. Differences between methods use the same resamples for both, so they are paired. The bootstrap treats rows as independent. They are not (they come in time order), so the intervals are narrower than the truth. Read them as a floor on the uncertainty.

Extra views, not used for any decision

  • Random split: the same procedure on a shuffled stratified 60/20/20 split, three seeds.
  • Rolling cut-offs: train on the first 50%, 60%, … 90% of rows and test on the next 10%, with settings fixed from the primary run.
  • Feature ablations: add or remove feature groups with settings fixed.

These reuse rows from the test and validation blocks after the main result was fixed. They explain it. They did not change it.

Results

Headline: the simple model matches the rule, and the complex one trails

Logistic regression has the best ROC-AUC (, interval to ), clearly above the rule (, interval to ), but on PR-AUC the paired difference between them is with an interval that straddles zero. In plain terms: the model orders the whole list better, but at the top of the list, where calls are placed, the one-line rule is just as good. Boosting is worse than logistic regression by PR-AUC, and that gap holds in every one of the resamples.

The scores are rankings, not probabilities

Both models were trained where about 5% of clients subscribed. On the test block about do, so their average predicted score ( for logistic, for boosting) is far too low. Their Brier scores ( and ) are no better than the that a constant guess of the test-block rate would score.

A probability cut-off is a bet that the score scale stays put. For each model I picked a cut-off on the validation block by maximising F1. What a random split would have said

Shuffling the rows and splitting at random lets training rows sit between the test rows in time. A model can then learn which period a row belongs to (the economy columns and the month are nearly a date stamp) and look up the answer.

The random split reports ROC-AUC near to and puts boosting ahead. The honest split reports and puts logistic regression ahead. A reader who trusted the random split would believe a stronger model and pick the wrong method.

Which inputs matter: ablations

  • duration is a leak. Adding the call length lifts logistic ROC-AUC from to . That jump is information from the future. It is not predictive skill.
  • campaign changes almost nothing, as the data section suggested.
  • The economy columns are ambiguous. For logistic regression they help on the test block ( versus ), and for boosting they hurt. Validation preferred leaving them out, and I followed validation. I do not read the test-block gain as evidence that they work. Every test row has a Euribor value outside the range seen in training (–% in training, –% in test). A linear model extends its line, which happened to point the right way. Trees hold the last value. Neither is learning the relationship.

Errors

This section examines the primary model (logistic regression) at a 20% call budget on the test block: the top clients by score. It reaches of all subscribers, and of its calls succeed.

Where it goes wrong

  • Most subscribers have no history. of test-block subscribers had never been contacted before, and they make up of the subscribers the list misses. For them the model has only weak signals, and it reaches of them. For previous successes it reaches .
  • The list sorts by month before it sorts by client. It calls every October client and nearly every March client, and few in May: it reaches only of May’s subscribers. That follows real differences between months (in the test block of October clients subscribed, against in May), but October’s effect was learned from just rows, and within a month the model has little to separate one client from another. With two and a half years of data I cannot tell seasonality apart from the timing of particular campaign waves.
  • Previous success is not a promise. Of previous successes who are called, subscribe again. The eight most confident wrong calls are all of this type.
  • Later periods are easier to reach. Reach is much higher in 2010 than in 2009, but subscribers are also about half of all 2010 clients, so any list is richer there.

Limitations

  • One bank, three years, and a regime change. The rate of subscription rises from to . I cannot tell from this file whether clients changed or whether the bank changed whom it called. The test block is a different world from the training block, so the headline numbers say how well a model transfers, and they would be different for any other cut.
  • Selection. Only clients who were phoned appear. The data cannot say how a never-called client would have responded, so the ranking is validated only on people the bank had already chosen to call.
  • Association, not cause. A feature that predicts is not a reason to subscribe. Contact channel, month and economy are tangled with time.
  • Uncertainty is understated. The bootstrap treats rows as independent, and they are not. Settings were tuned on one validation block that is itself unlike the test block.
  • Unreliable probabilities. Scores support ranking only. Using them as probabilities, or with a fixed cut-off, would fail.
  • Diagnostics are not independent. The rolling cut-offs and ablations reuse validation and test rows after the main result was fixed. They explain the result and are not a second test.
  • Fairness was not audited. The models use age, marital status, education and job. Prioritising calls on those could treat groups differently, and I did not measure that.
  • Sentinel and near-constant columns (pdays, default) are handled simply, and unknown may not be missing at random.

Conclusion

Using only information available before a call, logistic regression ranks later clients with ROC-AUC , above chance and above the one-line previous-success rule on that measure. It does not clearly beat the rule where it counts for a call list, and gradient boosting does worse than both. Added complexity did not pay for itself because the thing that changed between training and test was the world, not the model.

Three lessons carry over. First, a variable that makes a model look excellent (call duration) is a warning, not a gift. Second, the way the data is split can reverse which model looks best, so the split has to match how the model will be used. Third, a baseline that costs one line of code is the fastest way to see whether a model is earning its place.

If I continued: weight recent rows more, retrain on a schedule and monitor the subscription rate for drift, recalibrate scores on the latest period before using any threshold, and evaluate within later campaigns separately.

Reproduction

Everything on this page, every number and chart, is produced by one script and rendered from its output file, so the page and the code cannot drift apart. The run takes about four minutes on a laptop and is deterministic (fixed seed).

python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python analysis/run_analysis.py data/bank-additional-full.csv docs/data/results.json
